# U1 全景：Agent 就是"循环 + 工具箱"

> 学习线：用 Python 写 Agent 内核（OpenHands SDK 费曼精读）· 2026-10-11 开讲
> 定界：弄清 **`conversation.run()` 背后程序的循环到底在转什么**；讲清的证据 = 能向只会 SQL 的同事解释 agent 为什么是"循环 + 工具箱"。

## ① 是什么：把"下一步干什么"的决定权交给模型

传统自动化：**人写死每一步**——调度平台里的 DAG，哪个作业先跑、参数传什么，全是预先编排，机器只执行。

Agent 反过来：程序只剩**一个循环**和**一箱工具**，每轮循环问模型"根据目前进展，下一步干什么？"，模型说要调哪个工具，程序执行、把结果喂回去，再问下一轮。直到模型说"干完了"，循环结束。

**SQL 翻译官版**：传统自动化 = 手写 DAG；agent = 两步循环调度——"问模型下一步 → 执行 → 记账"，"下一步"从写死的依赖变成**模型现场决定**。工具 = 注册好的 UDF，模型 = "会写 SQL 但不碰生产、只能申请调 UDF 的实习生"。

## ② 解决什么痛点

让程序干没预料到的复杂任务（"把项目情况写进 FACTS.txt"），过去要穷举所有分支；agent 的解法是**不穷举，雇实习生**——给一份工具说明书让他自己决定。代价：实习生可能原地打转 → 所以要兜底（U6）。

## ③ hello world 逐行（核心 5 行，examples/01_standalone_sdk/01_hello_world.py）

```python
llm = LLM(model="gpt-5.5", api_key=...)          # ① 造"电话"：连哪家模型公司
agent = Agent(llm=llm, tools=[TerminalTool, FileEditorTool])  # ② 造"实习生"：发电话+工具箱
conversation = Conversation(agent=agent, workspace=cwd)  # ③ 开"工单"：在哪个目录干活
conversation.send_message("把项目 3 个事实写进 FACTS.txt")   # ④ 工单上写需求
conversation.run()                                 # ⑤ 实习生开始干活——循环在跑
```

## ④ run() 背后的六行伪代码

```python
while 干完了吗 == 否:
    回答 = llm.generate(历史消息, 工具清单)      # 实习生想：下一步干嘛？
    if 回答里带工具调用:
        结果 = 执行工具(名字, 参数)               # 干活
        历史消息.追加(结果)                       # 记账（喂回下一轮）
    else:
        break                                    # 实习生说做完了
```

ZCode、OpenCode、OpenHands、Claude Code 的内核剥掉工程外壳都是这个形状；差别在账本怎么记、工具怎么管、怎么防实习生发疯。

## ⑤ 两个真实的坑（伏笔）

1. **死循环**：模型可能连续 N 轮执行同一命令不停 → 源码里有专门机制治（名字带 "stuck"，U6 讲）
2. **工具说明书是给模型读的**：描述含糊 → 模型不会用/参数瞎填。工具文档的读者是 LLM，不是人

## 📒 语法债（回门0正课补）

- `LLM(...)` 大写名+括号 = "造一个东西然后贴标签"：`llm` 是标签，造出的东西自带配套功能（豪华字典）
- `llm=llm` 命名传参 = Oracle 命名参数，指名传值不看顺序
